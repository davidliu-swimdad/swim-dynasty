# Swim Dynasty — 游戏开发设计 / Developer design

## 1. 项目定位 / Vision

离线 NCAA 女子游泳教练经营游戏。玩家安排训练、培养运动员、排阵并参加比赛，长期目标是建立自己的王朝。真实公开成绩作为历史基线，游戏成长与现实记录严格分离。公开代码与独立数据采集系统分离；公开演示包使用虚构数据。

## 2. 当前状态 / Current documented status

依据现有 README 与双语 HTML 设计页：已提供中英文离线界面、浏览器存档、三组周训练、泳池和 dryland、减量、助教建议、模拟成绩与疲劳、个人和接力排阵、赛季及比赛数据包导入。比赛包支持历史结果对照；P0 跨季预测按年级离队、承诺入队及秋季基线计算 13 个个人项目与 5 个接力项目，尚不包含正式资格、预赛、跳水。上述为仓库文档记录，未在本次独立运行验收。

## 3. 本阶段目标 / Next milestone

从 2026-09-18 开档，逐周模拟多校及高中选手成长，推进至 2028 秋季并继续到 2029 春季 NCAA。每赛季暂只模拟 NCAA Championships。2028 秋季入学者首次常规 NCAA 为 2029 春季。保留已有 P0 预测功能，不把预测等同于完整跨季存档。

暂缓动态招募、转会、教练变动、奖学金、NIL、复杂关系事件。已知承诺按入学年份激活，未知去向不强行分配。

## 4. 数据范围与来源 / Data

- 以 2026 NCAA 女子 D1 A/B 决赛选手、接力学校及各项目全国前 30–50 名候选者为建议初始池；补充重点学校相关阵容和 2027/2028 承诺。实际覆盖根据数据审计决定，不宣称全 NCAA 覆盖。
- 优先复用现有 ARM 数据；补充官方 NCAA 赛果、学校 Athletics 名单和招募公告、SwimCloud、可核验官方成绩。记录来源、比赛日期、公开可获得时间、采集日期及缺失情况。
- 逻辑实体：Athlete（稳定 ID）、Performance（项目、泳池、时间、出处）、Commitment（学校、入学年、承诺日期）、Team、RosterMembership（起止、资格）、SimulationState。先检查现有 schema，避免重复建表。
- 固定开档数据版本；基线仅采用开档时已公开的成绩。未来真实 PB 不覆盖模拟状态。SCY/LCM/SCM 分开，转换标记估算。承诺信息同样记录时间；开档后已知承诺若用于固定情景，明确标为回顾式情景输入，不冒充开档已知信息。
- 不公开原始第三方数据库、凭证、私人资料或内部网络配置；核实数据再分发权利。

## 5. 统一成长引擎 / Shared growth engine

Stanford 由玩家安排训练，自动推进时使用选定模板；对手大学由 AI 生成周训练；高中选手采用简化俱乐部模板。三者尽量复用已有训练结算与成绩引擎，不为对手另设固定年度提升百分比。高中与大学阶段可有不同经校准的参数。

模板：短距离、中长距离、技术、均衡；根据项目、能力、潜力、适应性、负荷、恢复选择。允许停滞、退步与少数突破。先测逐周结算性能，必要时才批量优化；优化须验证与逐周结果一致性。

真实 PB、当前模拟能力、模拟 PB、近期成绩、累计成长分别保存。历史 PB 已含原有能力，不重复加成。新生入队保留高中成长，切换训练策略而不重置。随机种子与状态持久化。

## 6. 跨季生命周期 / Lifecycle

2026–27：现有大学队员与高中候选者共同成长，2027 NCAA 后处理资格与离队。
2027–28：2027 届入队，2028 届继续高中训练，2028 NCAA 后更新阵容。
2028–29：2028 届入队，继续成长至 2029 NCAA。

资格与毕业并非完全等价；首版按年级简化时明确限制。未入学者不得代表大学参赛。自动推进调用正常周结算，避免重复结算，保留独立存档或分支、可复现随机状态。目标日期包括年度 NCAA 与秋季入学。

## 7. NCAA 年度比赛 / Annual championship

从当季模拟实力重新筛选参赛者，不固定沿用 2026 决赛名单。逐步实现资格、个人项目限制、预赛、A/B Final、13 个人及 5 接力计分。首版简化资格须明确标注。无跳水时称 Swimming-only Standings。统一模拟成绩引擎考虑能力、疲劳、恢复、减量及随机发挥；校验 SCY 历史分布和纪录，纪录不是绝对硬上限。

历史挑战可在当场结算读取该场真实对手赛果，赛前不可见；自由王朝模式对手也模拟成长，两者明确区分。

## 8. 长期模型 / Long-term design

五层运动员档案：Ability、Traits、State、Skills、Profile。健康与疲劳独立；人际相性独立保存；真人心理、资助等未知信息不得伪装为事实。训练容量有限，恢复与专项培养有取舍；研究解锁方法，再经个人训练获得技能。教练六维：训练、战术、招募、管理、科研、沟通；未来支持委任成长、留任、转会、承诺履约、预算及设施。上述属于长期设计，非当前实现承诺。

## 9. 校准与报告 / Calibration and reports

利用可用历史数据按高中/大学年级、项目、初始水平估计年度成长分布，考虑停滞、退步、缺失与选择偏差；历史数据用于统计校准，不泄漏个体未来结果。参数尚未确定。

年度报告：运动员基线、模拟 PB、成长；球队离队/入队、项目深度、接力、积分及排名；模型成长分布、异常成绩、数据覆盖。比较 Stanford 与对手、高中与大学成长。

## 10. 实施与验收 / Implementation and acceptance

1. 审计现有代码、数据包和 ARM 数据覆盖。
2. 建立候选池与可追溯基线，导入承诺。
3. 扩展共享训练引擎与自动训练、高中成长。
4. 实现跨季阵容与可复现自动推进。
5. 扩展年度 NCAA 比赛及报告。
6. 历史校准与回归测试。

验收：相同存档、策略、种子可复现；无未来 PB 泄漏、重复结算或入学重置；毕业离队及入学正确；对手与玩家共用成长机制；长期成绩分布合理；2029 NCAA 体现 2028 新生。未确定参数、正式资格规则及数据覆盖须显式记录。保留现有运行功能，优先增量开发。
